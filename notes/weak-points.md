## 書き方 ── まず「軽い形」で書く

**既定はこれです。見出し＋1行＋2行。30秒で書けます。**

```markdown
## 008 sortが元の配列を壊す
2026-8-29 / JS基礎 / 解決

- 詰まった: sortは新しい配列を返すと思っていた
- 分かった: 元の配列を並べ替える。[...arr].sort() でコピーする
```

**「詰まった」「分かった」はアプリのメモと同じ言葉です。**
週末は、アプリからコピーした行に見出しと日付の行を足すだけで済みます。

### 3つのルールだけ守る

1. **タイトルは「何が」を書く。**「配列で詰まった」ではなく「sortが元の配列を壊す」
2. **「詰まった」には、正解ではなく自分の思い違いを書く。** ここが後で効く
3. **分からないままでも書く。** その場合は `未解決` にして「分かった」は空でいい

```markdown
## 009 useEffectの依存配列に何を入れるか決められない
2026-9-15 / React / 未解決

- 詰まった: 全部入れると無限ループ、空にすると古い値になる。基準が分からない
```

分野は `JS基礎 / TypeScript / React / Next.js / ツール` の5つから選びます。
参画後に「Reactで詰まったこと」を検索で引くための1行です。

## 厚く書くのは月に1〜2本でいい

**同じことで2回以上詰まったもの**だけ、下の001〜007のように項目を分けて書きます。

```markdown
- **日付**: / **分野**: / **状態**:
- **状況**: どの課題・どの場面で詰まったか
- **勘違い**: 何をどう思い込んでいたか
- **今の理解**: 正しくはどうなのか。自分の言葉で
- **再現コード**: 最小限のコードで再現する
```

**再現コードは、後で自分が動かして確かめたいものだけ。** 毎回は要りません。

軽い形で書いておいて、あとから厚くするのが一番続きます。**先に厚く書こうとして止まるのが一番よくない。**

## 003 `Object.prototype.toString.call()`

- **日付**: 2026-8-9
- **分野**: JS基礎
- **状態**: 解決済み
- **状況**: Ch3型判定チートシートの課題において `Object.prototype.toString.call()`について分からなかった
- **勘違い**:
- **今の理解**: あらゆる値の正確な型を [object Array] 形式の文字列で返す組み込みメソッド。typeof null === 'object' のような罠を回避できるため、null・配列・正規表現など紛らわしい型の判定に使う。
- **再現コード**:

```js
const values = [
	42, // 数値 number
	"hello", // 文字列 string
	true, // 真偽値 boolean
	null, // null
	undefined, // undefined
	[1, 2, 3], // 配列 array
	{ a: 1 }, // オブジェクト object
	function () {}, // 関数 function
];

// 要件2 & 3: 各値に3つの判定を適用し、console.table用の配列を作る

const result = values.map((value) => {
	return {
	値: String(value), // 見た目用
	typeof: typeof value, // 基本の型判定
	"Array.isArray": Array.isArray(value), // 配列かどうか
	"toString.call": Object.prototype.toString.call(value), // 正確な型判定
	};
});
```

## 004 ??と||の違い

- **日付**: 2026-8-11
- **分野**: JS基礎
- **状態**: 解決済み
- **状況**: ch4に置いてNull合体演算子??と論理和||を使用した際の動きの違い特に||で勘違いしていた
- **勘違い**: ||は通常の論理値(or)の動きと一緒と解釈でき、左辺がfalsyでも右がtrueかもしれないので右辺まで確認する結果**初期値(右辺)** が返される
- **今の理解**: ||は左辺がfalsyなら**右辺の値そのもの**を返す。真偽値ではない。
  ??は左辺が null か undefined のときだけ右辺を返すので、0 や "" は左辺のまま残る。
- **再現コード**:

```js
0 || false // → false（右辺が falsy でもそのまま返る）

0 ?? false // → 0 （0 は null/undefined でないので左辺を返す）
```

## 005 Reactにおいてのpropsのデフォルト値の使い分け(?? ||)

- **日付**: 2026-08-11
- **分野**: JS基礎（Reactで効く）
- **状態**: 解決済み
- **状況**: propsのデフォルト値を `||` で書くと、0 や "" を渡したときに意図せず既定値になる
- **勘違い**: 「値が無ければ既定値」のつもりで `||` を使っていたが、0 や "" も「無い」扱いになる
- **今の理解**: 0 や "" も有効な値として受け取る可能性があるなら `??` を使う。
  「0 や "" は未指定と同じ」と言い切れるときだけ `||` でよい。
- **再現コード**:

```js
// Reactのpropsをイメージした関数
function showItem(props) {
  const count = props.count || 5;   // 「countがなければ5」のつもり
  const label = props.label || "名無し";
  console.log(count, label);
}

showItem({ count: 3,  label: "りんご" }); // 3  "りんご"   ← 意図通り
showItem({ count: 0,  label: "" });       // 5  "名無し"   ← 意図と違う！
//                ↑ 0 と "" は falsy なので || が右辺を返してしまう

/*
  使い分けの判断基準
  | 状況                                 | 使うべき演算子 |
  |-------------------------------------|--------------|
  | 0 や "" も有効な値として渡す可能性がある  | ??           |
  | 0 や "" は「未指定」と同じ扱いでよい     | ||           |
*/
```

## 006 switch(true) の考え方

- **日付**: 2026-8-16
- **分野**: JS基礎
- **状態**: 解決済み
- **状況**: switch(true)の考え方がわかっていなかった
- **勘違い**: 通常のswitch文と同じ様に()の部分に値を入れてcaseの後と同じになれば良いと考えていた
- **今の理解**: switch(true)の()はあくまで"true"、通常とは逆の見方をするイメージ。通常は()の部分がcaseに合致するかを見るが、switch(true)はcaseが()に合致するか"true"になるかを見る。
  ※正しくは「逆」ではなく「case 側に条件式を書く使い方」と覚えると。claudeより
- **再現コード**:

```js
switch(true){
	case num % 15 === 0: //trueになるかどうかを見る
		console.log("FizzBuzz");
		break;
	case num % 3 === 0:
		console.log("Fizz");
		break;
	case num % 5 === 0:
		console.log("Buzz");
		break;
	default:
		console.log(num);
}
```

## 007 for ループ変数に `let` を付け忘れる

- **日付**: 2026-8-19
- **分野**: JS基礎
- **状態**: 解決済み
- **状況**: for文・for...ofのループ変数を宣言するとき、`let`/`const` を何度も書き忘れた
- **勘違い**: 変数名だけ書けば動くと思っていた（実際 non-strict mode では動いてしまう）
- **今の理解**: `let` なしだとグローバル変数になる。複数のループが混在するコードで意図せず上書きされるバグの原因になる。strict mode ではそもそも ReferenceError になる
- **再現コード**:

```js
// NG
for (i = 0; i < 3; i++) { }          // i がグローバルに漏れる
for (num of arr) { }                   // num がグローバルに漏れる

// OK
for (let i = 0; i < 3; i++) { }
for (const num of arr) { }
```
