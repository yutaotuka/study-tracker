# notes/ の使い方

**常設のノートはこの5つだけです。** 新しいファイルを作らないでください。

| ファイル | 何を書くか |
| --- | --- |
| `learning-log.md` | 日々の記録。週末にアプリからMarkdownを貼る |
| `weak-points.md` | つまずいた記録。番号を振って足していく（消さない） |
| `setup.md` | セットアップ手順集。次に同じことをするとき見る |
| `convert-log.md` | ★コンバートの判断理由（5週目に作る。参画後に一番使う） |
| `qa.md` | 想定質問への回答（5週目に作る。14週目に書き直す） |

書き方の詳細は `メモの書き方.md` を読んでください。

## v6で足すもの（自作アプリ側に置く）

フェーズA以降は、自作アプリのリポジトリ側にも記録が増えます。
これは上の5つとは別で、**アプリと一緒に読まれるもの**だからです。

| ファイル | 何を書くか |
| --- | --- |
| `tracker-app/docs/requirements.md` | 要件（6週目・課題A-1）。★作らないものとその理由も書く |
| `tracker-app/docs/design-log.md` | 設計の判断と理由。9週目の配布版との差分もここ |
| `tracker-app/docs/test-policy.md` | テスト方針（10〜13週目）。何をテストしないかも書く |
| `tracker-app/docs/review-log.md` | 自己レビューとAIレビューの判断（12週目・課題B-4） |

一時ファイルを1つだけ許しています。`notes/js-checklist.md`（14週目・課題C-1）です。
棚卸しが終わったら weak-points.md に反映して消して構いません。

## v2からの変更

v2の課題では `scope.md` `this.md` `useeffect.md` のように、
テーマごとに20近いファイルを作る想定になっていました。
書く場所を探すことが負担になっていたので、**`learning-log.md` に集約**しました。

既に作ってしまったファイルがある場合、中身を `learning-log.md` に移してから消すか、
そのまま残しておいても構いません。**これから増やさないことだけ守ってください。**
