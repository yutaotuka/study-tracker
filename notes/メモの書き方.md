# メモの書き方（これだけ読めば迷わない）

書きづらかった原因は3つありました。全部直しました。

| 原因 | 直したこと |
| --- | --- |
| 入力欄が1行で狭い | サマリーに大きな記録欄を作った。表をスクロールしなくていい |
| アプリとObsidianの二重書き | **平日はアプリだけ。** 週末にボタン1つでObsidianへ移す |
| どこに何を書くか迷う（20ファイルに散っていた） | **常設のノートを4つに絞った** |

---

## 1. 平日：アプリに1〜3行だけ

サマリータブの一番上、「今日やることの目安」の下に**「今日の記録」**があります。
日次ログのタブを開かなくても、ここで時間もメモも入れられます。

書くのはこの3つだけ。**全部埋めなくていい。**

```
詰まった: varのループで3,3,3になる理由が腑に落ちない
分かった: クロージャは作られた場所の変数を覚えている
明日: Ch8のthisから
```

「書き出し」の**ボタンを押すと行頭が入ります。** 続きを書くだけです。

**書くことが無い日は時間だけ入れてください。** それでも記録としては十分機能します。

---

## 2. 週末：ボタン1つでObsidianへ

日次ログタブの**「この範囲をMarkdownでコピー」**を押す → `notes/learning-log.md` に貼る。

貼るとこうなります。

```markdown
# 1週目（8/24〜8/30）

実施 14.5h / 目標 16h

## 8/24（月） 2.5h
JS基礎 1.5h / TS/React/Next 1h

- 詰まった: varのループで3,3,3になる理由が腑に落ちない
- 分かった: クロージャは作られた場所の変数を覚えている

## 8/25（火） 2h
...

## 終えた手順
- [コア][JS基礎] Ch7(スコープ)を読む
- [コア][JS基礎] 課題「スコープ可視化」…
```

**貼ってから整えます。** 週末の振り返り枠30分でやることは3つだけ。

1. 「詰まった」のうち**残したいもの**を `weak-points.md` に足す。
   貼った行に見出しと日付の行を付けるだけ（30秒）

   ```markdown
   ## 008 sortが元の配列を壊す
   2026-8-29 / JS基礎 / 解決

   - 詰まった: sortは新しい配列を返すと思っていた
   - 分かった: 元の配列を並べ替える。[...arr].sort() でコピーする
   ```

2. まだ解けていないものは `未解決` と書いて「分かった」は空のままにする
3. 来週に持ち越すことを最後に3行書く

**厚く書くのは、同じことで2回以上詰まったものだけ。** 月に1〜2本で十分です。

---

## 3. 常設のノートは5つだけ

| ファイル | 何を書くか | いつ書くか |
| --- | --- | --- |
| `learning-log.md` | 日々の記録。週末にアプリから貼る | 週末 |
| `weak-points.md` | つまずいた記録。番号を振って足していく（消さない） | 詰まったとき／週末 |
| `setup.md` | **セットアップ手順集。次に同じことをするとき見る** | 環境を作ったとき |
| `convert-log.md` | ★コンバートの判断理由 | 5週目 |
| `qa.md` | 想定質問への回答 | 6週目 |

**新しいファイルを作らないでください。** 迷ったら `learning-log.md` に日付見出しで足す。

### learning-log と setup の使い分け

**時間が経つと意味が薄れるもの**は `learning-log.md`。その日何をやったか、何に詰まったか。

**次に同じことをするとき見るもの**は `setup.md`。環境構築、コマンド、初期設定。
日付順に流れると探せなくなるので、用途の見出しで並べます。

判断に迷ったら「1か月後にこれを探すか？」で決めてください。探すなら `setup.md` です。

## 4. 何を書けばいいか分からないとき

### 良い例

```
詰まった: sortが元の配列を壊すのを知らずに2回並べ替えて結果がおかしくなった
分かった: [...arr].sort() でコピーしてから並べる
```

**具体的な現象と、具体的な解決が書いてあります。** 後で読んで思い出せます。

### 良くない例

```
Ch11をやった
配列メソッドは難しい
```

これは1週間後の自分が読んでも何も分かりません。
「何が」難しかったのかが無いと、弱点として拾えません。

### 迷ったらこの質問に答える

- **今日、手が止まったのはどこ？**（止まらなかったなら「止まらなかった」でいい）
- **調べて分かったことを、一言でいうと？**
- **明日の最初の一手は？**

3つとも1行で十分です。長く書こうとしないでください。

## 5. 参画後もこのまま使えます

10月以降は週6hに落としますが、**やることは同じ**です。

- 平日：業務で詰まったことを1行メモ（アプリの「今日の記録」でよい）
- 週末：溜まったメモから3つだけ選んで深掘り

詳しくは `参画後の学習計画_2026年10月-12月.md` を見てください。

**毎日のメモが最後の砦です。** 深掘りが止まっても、メモが残っていれば再開できます。

## 4. 理解度チェック（v6.1で追加）

1週目（9/14〜9/20）でTypeScriptに6.0時間入りました。時間は目標どおりです。
それでも「理解できているか不明」になったのは、手順の成果物が
「読了メモ」「〜できる」で、**判定できなかったから**です。

そこで**手順ごとに1問**、5〜10分のチェックを置きました。

### やること

手順を1つ終えたら、サマリーの「今日の理解度チェック」で答えます。

| 判定 | 意味 |
| --- | --- |
| ○ | 見ないでできた |
| △ | 詰まったが、調べて分かった |
| × | 分からなかった |

**×を押したときだけ、答えを書く欄が出ます。** そこに1行書いてください。

### ★×は失敗ではありません

×が出た日は、**穴が見つかった日**です。○ばかり並ぶ週より価値があります。

一番まずいのは「読んだ。たぶん分かった」で終わることです。
それが1週目に起きたことでした。

### 週末にやること

サマリーの「分からなかったこと（×）」を開いて、
**「×をMarkdownでコピー」**を押し、`weak-points.md` に貼ります。

貼ると、こういう形で入ります。

```markdown
### ★依存配列を空にして古い値を掴むバグを再現し、直す(課題R-2)

- 分野: React ／ 4週目
- 問い: 直したコードを閉じて、古い値を掴むバグをもう一度自分で再現させる。
- 分からなかった点: 依存配列に何を入れるかの基準が言えない
- 分かったこと:
```

**「分かったこと」は空のまま貼られます。** 後で埋めるための欄です。
埋まったら、そのときが本当に分かったときです。

### チェックの形式は4つ

| 形式 | やること |
| --- | --- |
| **予測** | 実行する前に結果を言う。当たれば理解している ★これが軸 |
| **再現** | 教材と自分のコードを閉じて、見ないで書く／話す |
| **説明** | 自分の言葉で1行。本の言葉で書けても○にしない |
| **穴埋め** | 概念系。`____` を自分の言葉で埋める |

**予測型が一番多いのは意図的です。** 読み返すより速く、しかも自分で判定できるからです。
`console.log` を足す前に予測する癖をつけると、実行1回ごとに確認が入ります。
