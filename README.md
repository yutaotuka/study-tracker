# 学習トラッカー

TypeScript / React / Next.js の学習計画v6（2026/9/14〜2027/1/10・全17週）を管理する静的Webアプリです。
ビルド不要・依存パッケージなしで、GitHub Pages にそのまま置けます。

## ★飛ばしたJSの章をどう扱うか

独習JavaScriptの飛ばした章は、**全部は埋めません。** 埋めるのは Ch15 と Ch10 の一部だけです。

そして**穴埋め専用の時間枠は作りません。** その章が必要になる機能を、フェーズAの要件に仕込んであります。

| 作る機能 | 開く章 | 時期 |
| --- | --- | --- |
| キーワード検索 | Ch10 正規表現 | 7週目 |
| 日付の絞り込み・並べ替え | Ch10 Date | 7週目 |
| フォームの送信 | Ch15 preventDefault | 8週目 |
| モーダル（外側クリックで閉じる） | **Ch15 イベント伝播** | 8週目 |
| Escキーで閉じる | Ch15 キーボードイベント・解除 | 8週目 |
| npm scripts | Ch17 npm | 10週目 |
| クラス構文を読む | Ch9 クラス | 14週目 |

該当する手順と課題には **「参照 Ch○○」のバッジ**が付き、その日の「今日やること」の下に
開く節と理由が自動で出ます。毎朝のブリーフにも出ます。**探しに行く必要はありません。**

方針の全体（どの章を埋めて、どれを埋めないか、理由つき）は**教材タブの「JSの復習方針」**で
いつでも見られます。

## 「その日の目安」について

週の**コアの手順だけ**を各日に自動配分しています。余力は日付を持ちません。

- 1日の目標は平日2.0h・土日2.5h（週15h）。年末年始（12/29〜1/3）は0h
- 週のコアの割り当ては目標より少なく置いてあります。**差がバッファ**です（全体で68h・28%）
- あくまで目安なので、前後に1〜2日ずれても問題ありません。週の合計が合っていればOKです
- 割り当てがゼロの日は**予備日**です。積み残しを片付けるか、休んでください
- 重いときの削る順番は 余力 → 振り返り。コアは死守します

配分ロジックは `day_plan.py`（リポジトリ外の生成スクリプト）にあり、
結果は `js/data.js` の `days[].plan` に埋め込まれています。

## データの保存と同期

進捗はまず **ブラウザの localStorage** に保存されます。そのうえで、端末をまたぐ方法が2つあります。

### 方法1：GitHub Gist と同期する（自動）

非公開のGistに進捗JSONを置き、開いたときに取得・変更したときに送信します。追加のサービスは不要です。

**すでにv1で接続している場合は、設定は不要です。**
トークンとGist IDはそのまま引き継がれ、進捗は同じGist内の
`study-progress-v2.json` に保存されます。v1の進捗ファイルは上書きされません。

**初回（1台目・まだ接続していない場合）**

1. GitHubで **Settings → Developer settings → Personal access tokens → Tokens (classic)** を開く
2. **Generate new token (classic)** を押し、スコープは **`gist` だけ** にチェック
3. 有効期限を設定して生成し、トークンをコピー
4. トラッカーの **同期設定** を開いてトークンを貼り、**接続** を押す
5. 非公開Gistが自動で作られ、**Gist ID** が表示されるので控えておく

> クラシックトークン（`gist` スコープ）を推奨します。fine-grained トークンはGist APIの対応が
> 環境によって異なるため、うまくいかない場合はクラシックを使ってください。

**2台目以降**

同期設定で、同じトークン（または同じアカウントの別トークン）と、控えておいた **Gist ID** を入力します。

**共用端末で使うとき**

「この端末にトークンを記憶する」の **チェックを外してください**（既定でオフ）。
外した場合トークンは sessionStorage にのみ置かれ、タブを閉じると消えます。
使い終わったら **接続を解除** を押すと確実です。

**競合したら**

別の端末が後から更新していた場合、上書き前に確認が出ます。中止すると相手の内容は壊れません。
相手の内容を取り込みたいときは、ページを再読み込みするか **同期** を押してください。

### 方法2：JSONファイルで持ち運ぶ（手動・トークン不要）

- ヘッダーの **書き出し** でJSONを保存し、別の端末で **読み込み**
- JSONファイルは画面に **ドラッグ＆ドロップ** しても読み込めます
- トークンを一切置きたくない場合はこちらだけで運用できます

### 注意

- トークンはこのブラウザ内にのみ保存され、GitHub以外には送信されません
- ブラウザのデータを消すと、未同期の進捗は失われます
- 同期状態はヘッダー下の帯に表示されます（未接続／同期済み／未同期の変更あり）

## 毎朝のブリーフをSlackへ送る（任意）

GitHub Actions が毎朝7時（JST）に、**今日のタスク・目標時間・進捗・未完了** をSlackへ送ります。
サーバーは不要で、無料の範囲で動きます。

送られる内容の例:

```
*学習ブリーフ 11/4（水）・8週目*
今週: 【A③】フォーム追加・モーダル・Escキー・localStorage・境界の引き直し
今日の目標 2.0h

*今日やること*
• [React] ★モーダルを作る。外側をクリックしたら閉じるようにする(課題A-5) — 2.5h

_詰まったら開く章（先に読まない）_
▸ Ch15 イベント ／ イベント伝播（バブリングとキャプチャ） — モーダル／ドロップダウン（外側クリックで閉じる）

*進捗*
• 昨日まで 96.0h / 105.0h（91%）
• 手順 58 / 112 完了
• 課題 20 / 43 完了

_今週の余力枠（コアが終わったら）_
◦ [振] キーボード操作とフォーカスの扱いを見直す — 1.5h
```

### 設定手順

**1. Slackの Incoming Webhook を作る**

Slackで「App」→「Incoming Webhooks」を追加し、通知したいチャンネルを選んで
`https://hooks.slack.com/services/...` のURLを control + C でコピーします。

**2. GitHubにシークレットを登録する**

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で3つ登録します。

| 名前 | 値 |
| --- | --- |
| `SLACK_WEBHOOK_URL` | 手順1でコピーしたURL |
| `GIST_ID` | トラッカーの同期設定に表示されているGist ID |
| `GIST_TOKEN` | `gist` スコープのクラシックトークン |

`GIST_ID` と `GIST_TOKEN` は進捗（実施時間・未完了）を読むために使います。
登録しない場合でも **今日のタスクと時間だけは送られます**。

> シークレットはリポジトリが公開でも第三者から見えません。ログにも出力されません。

**3. 手動で動作確認する**

**Actions → 学習ブリーフ（毎朝）→ Run workflow** で今すぐ実行できます。
Slackに届けば設定完了です。届かない場合はActionsのログを見てください。

### 補足

- 実行時刻は UTC 22:00（JST 翌7:00）です。GitHub Actions のスケジュールは
  混雑時に数分〜十数分遅れることがあります
- Discordを使う場合は `DISCORD_WEBHOOK_URL` を登録すれば同じ内容が届きます
- 「遅れ」は2種類に分けて報告します
  - **今週の積み残し** … 今日より前の日に割り当てられているのに未完了のもの
  - **過去の週** … 前の週までで未完了のもの
  - 今日の分は遅れに数えません
- 進捗は **Gistに同期された時点のもの** です。端末で入力しただけで同期していないと
  古い進捗が報告されます
- 時刻を変えたい場合は `.github/workflows/daily-brief.yml` の `cron` を編集します
  （例: JST 6:00 なら `0 21 * * *`）

## 計画を変更したいとき

`js/data.js` の `PLAN` を編集します。

- `weeks` … 週ごとの期間と学習内容
- `steps` … 週別タスク手順（`id` は進捗保存のキーなので変えると完了状態が外れます）
- `tasks` … 課題の要件定義（`track` が分野）
- `days` … 日次ログの行（`target` が1日の目標時間）
- `rules` … ルール画面の文言
- `references` … 教材（分野・URL・週・読む範囲）

日付をまるごとずらしたい場合は、生成スクリプト側の `plan_data.py` の `START_DATE` を変えて
`data.js` を作り直します。画面の期間表示は `days` から自動生成しているので、文言の修正は不要です。

## 実装メモ（読むときの手がかり）

学習教材として読めるように、独習JavaScriptで扱う内容を意識的に使っています。

- **Ch11 コレクション** … `filter` / `map` / `reduce` による集計（`render.js` の `weekStats`, `totalStats`）
- **Ch14 DOM** … `innerHTML` を使わず `createElement` + `textContent` のみで描画（XSS対策）。DOM生成は `utils.js` の `el()` に集約
- **Ch15 イベント** … `main` 要素1つにリスナーを付けるイベント委譲。検索と保存には自作 `debounce`
- **Ch16 モジュール** … 責務ごとにファイル分割。named export のみ使用
- **Ch13 非同期** … `sync.js` の `fetch` + `async/await` + `try/catch`。HTTPステータスごとにエラーを分けている。`importJson` の `File.text()` も同様

なお8〜10週目の課題は「このトラッカーをReactで作り直し、Next.jsへコンバートする」という内容です。
**10週目まではこのリポジトリのコードを開かないでください。** 先に見ると写経になります。
自分で作り終えてから読み比べると、設計判断の違いが学びになります。

日次ログの入力時は全体を再描画せず、合計セルだけを書き換えています。
再描画するとフォーカスが外れて入力が中断されるためです。

## テスト

`smoke_test.mjs`（リポジトリ外）で jsdom による動作確認を67項目、`sync_test.mjs` で同期の動作確認を30項目実施しています。
描画件数、フィルタの動作、保存と復元、集計の連動、入力中に再描画されないこと、日別配分の合計が手順の合計と一致すること、分野フィルタ、innerHTML非使用などを検証済みです。
同期側は fetch をモックし、トークンの保存先（記憶する／しない）、Gistの非公開作成、
取得と送信、競合時に上書きを止められること、401/403/通信失敗の扱いを検証しています。
